## 2. 测试目的

本次测试验证当前 SSLV 用户态接口及配套 SPI1 主机路径，在固定 mode 3、MSB-first 条件下的主从互联功能。验证范围包括：

1. 从机配置参数和 busy 状态保护。
2. 8/16/32-bit 主机到从机的基础接收。
3. 连续 disable/set-bpw/enable/receive 的重复 arm 稳定性。
4. 16-bit、128 word 长帧接收时的 RX FIFO 阈值读取与缓冲区推进。
5. 从机 TX FIFO 预装载后，从机 DT 到主机 MISO 的回传。
6. 同一帧中的 MOSI 和 MISO 双向独立校验。
7. 100 kHz 至 40 MHz 请求频率的接收扫描。

## 3. 测试环境和连线

| NAND 主机 | NOR 从机 | 说明 |
|---|---|---|
| PC15 SPI1 CLK | PB28 SSLV CLK | 时钟 |
| PC16 SPI1 MOSI | PB30 SSLV DR | 主机发送、从机接收 |
| PC17 SPI1 MISO | PB29 SSLV DT | 从机发送、主机接收 |
| PC14 软件 CS | PB31 SSLV CS | 片选 |
| GND | GND | 共地 |

主机端的 `SPI_IOC_MESSAGE` 完成并不单独代表从机收到了数据；本报告以从机 MOSI 比较结果、主机 MISO 比较结果和双方 suite 汇总共同判定。

## 4. 判定规则

每个传输 case 使用带递增 sequence 的非对称图样。16-bit 和 32-bit 数据均采用高字节在前的规范字节流；全双工时主机和从机使用不同图样流。因此，本次 `match` 同时说明当前 case 的长度、顺序、内容和方向均正确，不会被重复的固定数据掩盖。

| 输出 | 判定 |
|---|---|
| 从机 `result=match` | 当前 MOSI 到从机 DR 的数据完整且字节序符合期望 |
| 主机 `miso=match` | 当前从机 DT 到主机 MISO 的数据完整且图样符合期望 |
| `result=clocked` | 从机 TX 图样已被主机时钟驱动；MISO 数据正确性由主机 `miso=match` 确认 |
| suite `PASS` | 该组的所有 case 通过 |
| overall `PASS` | 所有七个概念测试组通过 |

### 5.2 配置检查

从机 `01_config` 执行以下负测试：

| 检查项 | 期望 | 本次结果 |
|---|---|---|
| 设置 mode 0/1/2 | 驱动拒绝 | PASS |
| 设置 bpw=3 | 驱动拒绝 | PASS |

结论：当前测试涉及的 mode 3、bpw 8/16/32 配置前提成立，非法配置和 busy 状态没有被错误放行。

### 5.3 基础接收和位宽覆盖

`02_basic_rx` 依次执行 3 个 case：8-bit x 8 word、16-bit x 8 word、32-bit x 8 word，方向均为主机 MOSI 到从机 DR。

从机 case 0、1、2 均记录为 `result=match`；主机三次 `SPI_IOC_MESSAGE` 均完整返回并释放 CS。

结论：在本次图样和 mode 3 下，8/16/32-bit 的基础数据内容、word 内字节顺序和 bit 顺序均未发现异常。

### 5.4 重复 arm 与帧边界

`03_rearm` 共执行 15 个 case：`8 -> 16 -> 32 bit` 为一轮，连续 5 轮，case 编号为 3 至 17。

从机原始报告中 case 3 至 case 17 均为 `result=match`。

结论：本轮没有观察到位宽切换后首帧丢失、上一帧残留、sequence 错位或 32-bit 返回 8-bit 时的帧边界错误。

### 5.5 长帧接收

`04_long_rx` 使用 16-bit x 128 word，即每帧 256 byte，共两帧（case 18、19）。

| case | 主机发送长度 | 从机结果 |
|---:|---:|---|
| 18 | 256 byte | `match` |
| 19 | 256 byte | `match` |

结论：在两帧 256 byte 传输中，RX FIFO 阈值触发、重复读取和接收缓冲区推进正常；未出现短接收、尾部错误或多次 IRQ 取数错位。

### 5.6 从机发送

`05_slave_tx` 使用 16-bit x 8 word，共两帧（case 20、21）。从机在接收等待前把从机专用图样写入 TX FIFO；主机在同一次 SPI message 内从 MISO 接收并比较。

| case | 从机日志 | 主机日志 |
|---:|---|---|
| 20 | `result=clocked` | `miso=match` |
| 21 | `result=clocked` | `miso=match` |

结论：从机 TX FIFO 预装载、PB29 DT 输出、PC17 MISO 输入及主机 MISO 比较路径均正常。

### 5.7 全双工

`06_duplex` 使用 16-bit x 8 word，共两帧（case 22、23）。主机向 MOSI 发送主机图样，同时从 MISO 接收从机图样；从机同时接收 MOSI 并输出预装载的从机图样。

| case | 从机 MOSI 结果 | 主机 MISO 结果 |
|---:|---|---|
| 22 | `match` | `miso=match` |
| 23 | `match` | `miso=match` |

结论：本次两帧全双工中，PC16 -> PB30 与 PB29 -> PC17 两个方向均完成独立图样校验，没有发现方向串扰、单向失效或图样混淆。

### 5.8 请求频率扫描

速度扫描使用 8-bit x 8 word、RX 方向，每个请求频率执行一个 case。

| 请求频率 | case | 主机结果 | 从机结果 |
|---:|---:|---|---|
| 100 kHz | 24 | PASS | `match` |
| 1 MHz | 25 | PASS | `match` |
| 10 MHz | 26 | PASS | `match` |
| 25 MHz | 27 | PASS | `match` |
| 40 MHz | 28 | PASS | `match` |

结论：本次测试中，五个请求频率点均完成主机到从机的数据校验。

重要限制：以上是 **spidev 请求频率**，不是示波器测得的实际 SCLK。X2600 主机驱动使用 `div_ssi` 和整数 CGV 分频；若 `div_ssi` 为 100 MHz，40 MHz 请求可能被选为 50 MHz。故本次结果不能替代实际 SCLK、占空比和时序的波形验收。

## 6. 结论

在本次接线、软件版本和执行条件下，主从 suite 的全部 12 个汇总检查通过：

- mode 3 和 bpw 配置约束符合预期；
- 8/16/32-bit MOSI 到 DR 接收正确；
- 连续重 arm 和跨位宽切换正确；
- 16-bit x 128 word 长接收正确；
- 从机到主机的 MISO 回传正确；
- 双向全双工数据正确；
- 100 kHz、1 MHz、10 MHz、25 MHz、40 MHz 请求频率点均通过本项目的数据校验。

因此，可以判定当前主从连接在本测试覆盖范围内功能正常。

## 7. 未由本次结果证明的能力

本次通过不等于完成所有 SSLV 功能或板级高速资格验证。以下项目没有被本次 suite 覆盖：

- mode 0/1/2、LSB-first、SSP、Microwire、硬件 loopback；
- SSLV DMA、callback 接收、RX/TX overflow 或 underflow 的异常返回；
- 进程异常退出、多进程并发、休眠恢复和长时间老化；
- 实际 SCLK、CS 建立保持时间、占空比、边沿质量、电平、过冲和振铃；
- 协议层 CRC、流控、重传和错误恢复。

后续如需将“40 MHz 请求通过”升级为“40 MHz 板级时序合格”，应同时归档主机侧 `div_ssi_rate`、驱动实际分频日志，以及 CLK/CS/MOSI/MISO 的逻辑分析仪或示波器波形。
